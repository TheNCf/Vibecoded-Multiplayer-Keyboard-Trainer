# Keyboard Trainer

Локальная система обучения набору текста: преподаватель (админ) запускает «сессии» и наблюдает за результатами учеников в реальном времени в стиле Kahoot, ученики печатают тексты на своих устройствах через Wi-Fi.

## Возможности

**Ученик (`/user`):**
- вход по псевдониму + персональному коду;
- выбор текста (рус/англ, 3 уровня сложности);
- тренажёр с подсветкой символов, живыми симв/мин, точностью и ошибками;
- во время активной сессии — общий счётчик символов и полоса «мой вклад»;
- экран результата после каждой попытки.

**Преподаватель (`/admin`):**
- вход по паролю;
- кнопки «Начать / Завершить сессию»;
- крупный счётчик общего числа символов за сессию;
- живая таблица участников: символы, % вклада, симв/мин, точность;
- всплывающие надписи с псевдонимами учеников при каждом правильном наборе (Kahoot-стиль);
- при завершении — обязательная подпись сессии, автосохранение в архив;
- архив сохранённых сессий и сводная статистика;
- вкладка «Тексты» — создание, редактирование и удаление текстов для печати;
- вкладка «Настройки» — переключатель «Показывать таблицу участников»: когда выключен, на дашборде не видно индивидуальной статистики учеников (удобно при проекции экрана). Выбор запоминается в браузере.

## Стек

Node.js, Express, MongoDB (mongoose), Socket.IO, vanilla HTML/CSS/JS.

## Быстрый старт

```bash
npm install
cp .env.example .env      # отредактируйте DB_URI и ADMIN_PASSWORD
npm run seed              # заполнить текстами и тестовым учеником (нужен MongoDB)
npm run dev               # или: npm start
```

Затем на устройствах в одной Wi-Fi-сети:
- ученики: `http://[server-ip]:3000/user`
- преподаватель: `http://[server-ip]:3000/admin`

IP сервера прописывается в `.env` (`NETWORK_IP`) и выводится в консоль при запуске.

### Запуск в Docker

Docker запускает **только приложение**. База данных — ваша локальная MongoDB на компьютере (Docker-контейнер подключается к ней через `host.docker.internal`). Папки `user/`, `admin/`, `public/` (и серверный код) смонтированы как volumes — правки видны без пересборки образа.

Сначала убедитесь, что MongoDB запущена на хосте:

```bash
brew services start mongodb-community   # если ещё не запущена
```

Затем:

```bash
cp .env.example .env          # задайте ADMIN_PASSWORD, при желании JWT_SECRET
npm run docker:up             # сборка/запуск с автоопределением IP в локальной сети
docker compose logs -f server # логи сервера
docker compose down           # остановка
```

`npm run docker:up` сам подставляет текущий IP компьютера в `NETWORK_IP`, поэтому адрес в логах всегда актуален при смене Wi-Fi. Если запускаете обычным `docker compose up -d`, IP берётся из `.env` — при смене сети обновите его.

**Правки фронтенда** (`user/`, `admin/`, `public/`) применяются сразу после обновления страницы (Cmd+Shift+R). **Правки серверного кода** (`server/`, `database/`) — после `docker compose restart server`. Пересборка (`--build`) нужна только при изменении зависимостей в `package.json`.

Внутри контейнера `DB_URI` переопределяется на `mongodb://host.docker.internal:27017/keyboard-trainer`, то есть используется ваша хостовая база. Приложение доступно так же, как при локальном запуске: `http://[ip-хоста]:3000/user` и `/admin`.

Тексты меняются либо через вкладку **«Тексты»** в админке, либо командой синхронизации (см. ниже).

> **Сменили Wi-Fi?** IP компьютера меняется. Просто запускайте стек командой `npm run docker:up` — она сама определит новый IP и подставит в `NETWORK_IP`, поэтому адрес в логах всегда актуален. При локальном запуске (`npm run dev`) IP тоже определяется автоматически.


### Без MongoDB

Сервер запускается и без базы: используются встроенные тексты и in-memory пользователи/архив (история и данные сессий не переживают перезапуск). Для полноценной работы укажите `DB_URI` (локальный `mongod` или MongoDB Atlas).

## Переменные окружения (`.env`)

| Переменная | Описание |
|---|---|
| `PORT` | Порт сервера (по умолчанию 3000) |
| `DB_URI` | Строка подключения MongoDB |
| `ADMIN_PASSWORD` | Пароль преподавателя |
| `JWT_SECRET` | Секрет для токенов админа (если пусто — используется `ADMIN_PASSWORD`) |
| `NETWORK_IP` | IP сервера в локальной сети (для подсказок) |
| `AUTO_SEED` | Автозаполнение текстов при старте, если БД пуста (`true` в Docker) |
| `SEED_DEMO_USER` | Создавать демо-ученика `Тест`/`1234` при seed |

## Сценарий занятия

1. Преподаватель открывает `/admin`, нажимает **«Начать сессию»**.
2. Ученики входят в `/user`, выбирают текст и печатают — на экране преподавателя мгновенно появляются всплывашки с псевдонимами и растёт общий счётчик.
3. **«Завершить»** → ученики вводят подпись сессии (например «2Б, урок 3») → итоги автоматически сохранены.
4. Вклад **«Архив сессий»** — список всех сохранённых сессий.

## Управление текстами

Тексты хранятся в MongoDB (коллекция `texts`) и редактируются во вкладке **«Тексты»** админ-панели: добавить, изменить, удалить. Изменения сразу подхватываются у учеников (сигнал по Socket.IO).

Файл `database/defaultTexts.js` — это **стартовый набор** и «сброс»:

- при первом запуске (пустая база) тексты заливаются автоматически;
- команда `npm run seed` **приводит базу в точное соответствие файлу** — обновляет/добавляет тексты и **удаляет всё, чего нет в файле** (включая созданное через админку). Запускайте осознанно.

Обычный перезапуск сервера тексты не меняет, поэтому правки из админки сохраняются.

## Структура

```
server/          Express + Socket.IO, роуты, сервисы, менеджер раунда
database/        подключение, seed, встроенные тексты
admin/           интерфейс преподавателя
user/            интерфейс ученика
public/          общие стили/скрипты, локальный клиент Socket.IO
Dockerfile       образ приложения (multi-stage, production)
docker-compose.yml  приложение + MongoDB с volume
```

## Будущее: личный прогресс

Индивидуальная история учеников сейчас не хранится, но архитектура готова:
`server/services/progressService.js` — заглушка, вызовы уже подключены к завершению попытки;
`server/routes/results.js` — роут-заготовка; в документах раундов сохранён `userId`.
Достаточно реализовать сервис и создать коллекцию `results`.
