# План реализации Keyboard Trainer

## Стек и технологии

- **Frontend:** HTML, CSS, vanilla JavaScript (без сборки), две отдельные страницы: `admin/`, `user/`
- **Backend:** Node.js + Express
- **БД:** MongoDB (подключение через `DB_URI` из `.env`)
- **Реалтайм:** Socket.IO (события набора, всплывающие надписи, счётчики)
- **Сеть:** сервер слушает `0.0.0.0:3000`, доступен по `http://[server-ip]:3000`
- **Клиент Socket.IO раздаётся локально из `/public`** — без CDN, проект работает в Wi-Fi без интернета

## Модель данных (MongoDB)

- **texts** — `title, content, level (лёгкий/средний/сложный), lang (ru/en)`
- **users** — `alias, code, createdAt`
  - вход ученика по **псевдониму + персональному коду**, первый вход = регистрация
- **rounds** — `startedAt, finishedAt, label, totalChars, participantsCount, avgCpm, avgAccuracy, participants: [{ alias, userId, chars, cpm, accuracy, share }]`
  - `label` — **подпись сессии**, вводится админом в диалоге завершения (обязательное поле)
  - `userId` внутри участника — «крючок» для будущего личного прогресса
- **results** — на этом этапе **не создаётся** (личный прогресс не нужен)

## Архитектура под будущий личный прогресс

1. **`services/progressService.js`** — интерфейс-заглушка:
   ```js
   recordAttempt({ userId, textId, cpm, accuracy, ... })  // сейчас — no-op
   getHistory(userId)                                      // сейчас — пустой массив
   ```
   Вызов `recordAttempt` ставится в точку завершения упражнения учеником.
   Когда понадобится прогресс — реализуем внутри сервиса (создадим коллекцию `results`), не трогая UI и API-слои.
2. События Socket.IO и документ раунда уже содержат `userId` / `textId` — история собирается без миграций.
3. Роуты будущего (`GET /api/results?userId=`) выделены в отдельный файл `routes/results.js` — на этапе MVP отдают 501/пусто.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/texts` | список текстов для тренажёра |
| POST | `/api/users/login` | вход по псевдониму + коду (первый вход = регистрация) |
| POST | `/api/rounds/start` | старт раунда (админ) |
| POST | `/api/rounds/finish` | финиш + диалог подписи → автосохранение в архив (админ) |
| GET | `/api/rounds/current` | текущее состояние раунда |
| GET | `/api/rounds/archive` | список сохранённых сессий (админ, новые сверху) |
| POST | `/api/admin/login` | вход админа (пароль из `ADMIN_PASSWORD`), выдаёт JWT |
| GET | `/api/admin/stats` | сводка для дашборда |

## Механика раунда (Kahoot-режим)

Сервер хранит активный раунд в памяти (`server/rounds.js`):

```js
{
  id, startedAt, status: 'active' | 'finished',
  totalChars: 0,           // суммарно верных символов за раунд
  participants: Map<userId, { alias, chars, cpm, accuracy }>,
}
```

### Socket.IO

- Ученик шлёт `type { chars }` **батчами (дебаунс ~200 мс)**, а не на каждый символ.
- Сервер увеличивает счётчики и рассылает:
  - **админу:** `popup { alias, chars }` — всплывающая надпись с псевдонимом;
  - **всем:** `tick { totalChars, participants }` — раз в 1 с (счётчики и живая таблица).
- `round:started` / `round:finished` — сигналы ученикам.

### Дополнительные правила

- На каждый правильный символ упражнения ученика фиксируется вклад в раунд.
- Если раунд не активен — счётчики у ученика скрыты, идёт обычная запись (история пока пуста через `progressService`).
- Завершение раунда **автоматически сохраняет** итоги в архив (отдельной кнопки «Сохранить» нет).

## UI: User (`user/`)

1. **Вход:** псевдоним + персональный код.
2. **Выбор текста:** карточки с уровнем и языком (ru/en).
3. **Тренажёр:**
   - посимвольное сравнение с эталоном, подсветка верных/ошибочных символов;
   - live-счётчики симв/мин, accuracy, ошибок;
   - во время активного раунда — **общий счётчик раунда** и полоса **«твой вклад»**;
   - завершение по финальному символу или кнопке «Стоп».
4. **Экран результата:** симв/мин, точность, ошибки + «Ещё раз».
5. **Мой прогресс:** раздел есть, но данные пусты (заглушка `progressService`) — место под будущий функционал.

## UI: Admin (`admin/`)

1. **Вход по паролю.**
2. **Дашборд (Kahoot-экран):**
   - кнопки **«Начать раунд» / «Завершить раунд»**;
   - **крупный общий счётчик символов** с анимацией прибавления;
   - **живая таблица участников:** псевдоним, символы, % вклада, симв/мин — сортируется на лету;
   - **слой всплывающих надписей:** пузыри вида «Артём +12», буфер одновременно до 5–7, рандомная позиция, CSS-анимация fade-in → подъём → исчезновение;
   - карточки: всего учеников, средняя скорость (симв/мин), средняя точность.
3. **Завершение раунда** → модалка **«Подпись сессии»** (напр. «2Б, урок 3», обязательна) → автосохранение.
4. **Архив сессий:** простой список сохранённых раундов: подпись, дата, символы, участников, средняя скорость/accuracy (без детального экрана). Новые сверху.

## Порядок шагов

1. **Каркас:** `package.json`, `.env.example` (`PORT`, `DB_URI`, `ADMIN_PASSWORD`, `NETWORK_IP`), Express на `0.0.0.0:3000`, раздача `/admin`, `/user`, `/public`.
2. **БД:** подключение mongoose, схемы `texts` / `users` / `rounds`, `database/seed.js` (6–9 текстов ru/en, тестовый ученик).
3. **REST API:** texts, users, admin login, rounds (start/finish/current/archive), заготовка `routes/results.js`.
4. **Socket.IO:** менеджер раунда `rounds.js`, события `type` / `popup` / `tick`, `round:*`.
5. **User UI:** вход → выбор текста → тренажёр с фидбеком → результат (+ точка вызова `progressService`).
6. **Admin UI:** дашборд с Kahoot-механикой → модалка подписи → архив сессий.
7. **Проверка по сети:** `npm run dev`, доступ с телефона/второго ПК по IP; задержка всплывашек ≤ ~300 мс, мобильная вёрстка.
8. **Финал:** README (запуск, seed, доступ по IP), сверка AGENTS.md с фактическим кодом.

## Зафиксированные решения

- MongoDB как NoSQL-БД
- Идентификация ученика: псевдоним + персональный код (без пароля); админ — пароль из `.env` + JWT
- Объём MVP: тренажёр + статистика + Kahoot-механика
- Реалтайм через WebSocket/Socket.IO
- «Сессия» = раунд, запускаемый кнопкой админа
- Сохранение итогов: автосохранение при финише, в документе агрегаты + подпись сессии
- Просмотр: только список архива, без детального экрана
- Личный прогресс учеников сейчас не хранится, но архитектура (сервис, роуты, userId в данных) готова к его добавлению
